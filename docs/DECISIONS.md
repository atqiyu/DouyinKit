# 决策记录（ADR）

## ADR-001：解析核心采用纯本地 WebView

**状态**：已采纳

**背景**：参考 `douyin-resolver-api` 用 Playwright 捕获详情接口。Android 端可选薄客户端 + 本地服务、纯 WebView、或纯 HTTP 复刻签名。

**决策**：纯本地 WebView。`ParseActivity` 加载桌面版作品页，document-start 注入 hook 捕获详情 JSON；页面模型/SSR 兜底。

**原因**：
- 用户要求不依赖电脑；
- 详情签名（a_bogus、x-secsdk-web-signature）由页面真实 JS 生成，纯 HTTP 不可靠；
- 分享页纯 HTTP 只有带水印视频、无码率档/LivePhoto/BGM 直链。

**后果**：
- 解析成功率取决于 WebView 能否通过抖音风控；页面改版可能需要更新 JS；
- 解析必须在前台进行；
- 需要维护验证码人工处理入口和诊断信息。

## ADR-002：compileSdk 36 + 固定依赖矩阵

**状态**：已采纳

**决策**：
- compileSdk/targetSdk 36，minSdk 24，AGP 8.13.2，Gradle 8.13；
- Compose BOM 2026.06.01（UI 1.11.4 / Material3 1.4.0），Navigation 2.9.8，Activity 1.12.4；
- Kotlin 2.3.21，KAPT；
- Coil 3.4.0，OkHttp 5.4.0，Media3 1.11.1，Room 2.8.5，DataStore 1.3.0；
- kotlinx.serialization 1.11.0。

**原因**：
- Compose UI 1.12 / Navigation 2.10 / Coil 3.6.3 要求 compileSdk 37 + AGP 9.1；
- Kotlin 2.4 元数据版本 2.4 超出 Room 2.8.5 的 `kotlin-metadata-jvm` 2.3 支持范围，KAPT 直接失败；
- `kotlinx-serialization 1.12.0` 强制 stdlib 2.4.10，进一步固化该冲突；
- 该组合在 compileSdk 36 上构建、测试、Lint 均通过。

**后果**：
- 依赖升级需同时检查 AAR `minCompileSdk` / `minAGP`、Room metadata、serialization stdlib 约束；
- 不能单独把 Kotlin 升到 2.4 或 Compose 升到 1.12；
- targetSdk 36 可在 Android 16/17 设备运行，但不是 API 37 行为级别。

## ADR-003：后台下载不自动重新解析

**状态**：已采纳

**背景**：签名直链约 1 小时过期；后台服务无法可靠运行 WebView。

**决策**：下载全部镜像失败且为 401/403/410 时标记 `NEEDS_REFRESH`，通知/UI 提示用户回前台重新解析；不在服务里创建 WebView。

**后果**：用户需在前台刷新过期链接；已下载文件不受影响。

## ADR-004：清晰度按视频短边判断

**状态**：已采纳

**背景**：竖屏视频 1080P 的宽高是 1080×1920；原逻辑按 height 判断会把 576×1024 误标为 1080P，默认档位也会选错。

**决策**：`VideoGear.shortSide = min(width, height)`，标签与 `VideoGearSelector` 均按短边匹配（1080P = 短边 1080）。

**后果**：横屏/竖屏标签一致；测试覆盖 1080×1920 与 576×1024。

## ADR-005：BGM 直链优先，缺失时 remux 视频音轨

**状态**：已采纳

**决策**：优先 `music.play_url`；缺失或下载失败时下载选中视频到临时目录，用 `MediaExtractor` + `MediaMuxer` 把第一条音轨无损封装为 `.m4a`。

**原因**：不引入 ffmpeg/原生库；设备兼容且体积可控。

**后果**：输出格式为 M4A（而非 MP3）；图文作品若既无音乐直链又无视频，则无法提取，明确提示。

## ADR-006：前台服务 dataSync + 2 并发

**状态**：已采纳

**决策**：`DownloadService` 使用 `foregroundServiceType="dataSync"`，固定 2 并发；一次性下载任务在服务内串行排队。

**后果**：Android 14+ 需要 `FOREGROUND_SERVICE_DATA_SYNC`；Android 15 dataSync 有 6 小时上限（本应用远低于）；并发设置暂未开放到 UI。

## ADR-007：URL 白名单与 SSRF 防护

**状态**：已采纳

**决策**：媒体下载只允许 `douyinvod.com`、`douyinpic.com`、`douyinstatic.com`、`snssdk.com`、`byteimg.com`、`ibytedtos.com`、`bytecdn.cn`、`douyin.com`、`iesdouyin.com` 及其子域；拒绝 IP 字面量、localhost、未知重定向目标。

**后果**：新 CDN 域名需要在 `UrlPolicy` 增加；避免恶意页面让 App 请求内网地址。

## ADR-008：仓库配置阿里云镜像

**状态**：已采纳

**决策**：`settings.gradle.kts` 优先使用阿里云 Google/Public/Gradle Plugin 镜像，保留 `google()` / `mavenCentral()` / `gradlePluginPortal()` 回退。

**原因**：当前网络从官方源下载依赖极慢（<1MB/min），镜像 20–30MB/s。

**后果**：镜像缺失的新构件会自动回退官方源；依赖校验仍由 Gradle 按 Maven 校验和完成。

## ADR-009：底部标签页保留 Composition，剪贴板监听上提

**状态**：已采纳

**背景**：早期用 `AnimatedContent` 包裹整页，切换时销毁并重建页面；资料库/下载页每次都要在主线程重新反序列化全部 Room 快照，剪贴板监听也随首页销毁而重置，造成切页卡顿和横幅重复/丢失。

**决策**：
- `MainScreen` 记录已访问的标签页，保留其 Compose Composition；未显示的页面用零尺寸 layout 跳过测量和绘制；
- 切换只改变 zIndex/alpha/轻微位移，约 180 ms，不再重建整页；
- `HistoryRepository` / `DownloadHistoryRepository` 加进程内 LRU 解码缓存；
- 剪贴板监测上提到 `MainScreen`，在 `ON_START`/`ON_RESUME` 和 `OnPrimaryClipChangedListener` 时读取，横幅状态与已读签名跨标签保留；
- 资料库详情页和解析结果页都作为覆盖层显示，底层标签页保持存活，返回键由覆盖层消费。

**后果**：切页不再触发整页重建和重复 JSON 解码；首次访问仍会有一次布局/图片解码成本。完全后台时 Android 10+ 禁止读取剪贴板，只能回到前台补读。

## ADR-010：下载页按作品聚合，视频封面用 Coil 视频帧

**状态**：已采纳

**决策**：下载记录按 `aweme_id` 分组；同一组内展示多个清晰度/图片/LivePhoto/BGM。作品预览用 `WorkPreviewDialog`：播放器为自定义交互的 Media3 PlayerView，文件详情列出尺寸、帧率、编码、时长、格式和大小。视频作品没有下载封面时，用 `coil-video` 从本地 MP4 解码封面帧；有远程封面时先作为占位。

**后果**：下载页从“任务列表”变为“作品列表”；网格/列表偏好写入 DataStore。视频帧解码首次需要几百毫秒到数秒，期间显示远程封面或类型占位图。

## ADR-011：重复下载按媒体内容识别并提供三种策略

**状态**：已采纳

**背景**：同一作品经常被反复解析，用户可能已经下载过某个清晰度、图片或 BGM；直接再下载会产生无意义的重复文件，而直接覆盖又有下载失败丢文件的风险。

**决策**：
- 用稳定的媒体 key 识别重复：视频按“分辨率 + 编码 + 帧率”，图片/动图按索引，BGM/封面/ZIP 各一个 key；
- UI 在入队前查询 Room + 内存注册表，发现重复时提供“跳过 / 覆盖 / 重复下载”；
- 跳过时，视频/BGM/封面请求直接省略，图集请求写入 `skipMediaKeys`，引擎只下载缺失项；
- 覆盖时把旧文件引用写入 `replaceFiles`，新任务下载到新文件；只有任务完整成功（无警告）后才删除旧文件并清理旧记录；
- 重复下载不做特殊处理，与旧文件并存。

**后果**：覆盖失败或部分失败时不会丢旧文件；新文件名可能因 MediaStore 去重出现 `_1` 后缀。清理记录和物理文件是独立选项，由下载管理界面控制。

## ADR-012：作品预览的操作层级与 LivePhoto 内联播放

**状态**：已采纳

**决策**：作品预览把详情/分享/打开放到右上角，左下角只保留作品信息并提供眼形按钮控制渐隐；文件级详情只在“详情”面板展示。LivePhoto 在图片 Pager 内使用 TextureView 循环播放，点击图片开始，再次点击不暂停，横向滑动交给 Pager 处理。

**后果**：图片预览更接近抖音的信息层级；TextureView 比 SurfaceView 更适合在可滚动 Pager 内播放。1.4 起隐藏信息时，除显示/隐藏按钮外，退出按钮、标题、详情/分享/打开、图片页码和动图提示全部隐藏；显示/隐藏按钮保持 58%–82% 透明度，避免遮挡内容。

图文作品预览会通过 `AutoLoopingAudio` 自动循环播放 BGM。播放 LivePhoto 内联视频时 BGM 继续循环；内联动图播放器不请求音频焦点且音量为 0，避免两路声音叠加或 BGM 因焦点丢失而停顿。切换到视频/音频内容或打开音频试听时暂停，回到普通图片后继续；Activity 后台时暂停，回前台恢复。BGM 优先使用已下载音频，缺失时回退到作品 `music.playUrls`。

## ADR-013：下载页排序与自定义合集

**状态**：已采纳

**背景**：下载页按作品聚合后，作品数量较多时只能按最新下载顺序浏览；用户需要按大小/文件数/标题等维度查找，也希望把下载内容按自己的主题分类。

**决策**：
- 排序在内存中对 `DownloadGroup` 执行，支持最近/最早下载、文件最大、文件最多、标题、作者六种模式；模式保存到 DataStore，不改变底层任务记录。
- 合集与下载记录解耦：`download_collections` 保存合集，`download_collection_members` 以 `awemeId` 为主键保存单一归属；删除合集只删除成员关系，不动 `download_history` 或本地文件。
- 长按作品卡片的 `WorkPartsSheet` 增加“移动到合集”，合集选择面板包含“未分类”和“新建合集并移动”；顶部芯片提供全部/未分类/各合集筛选。
- 新建/重命名合集校验空名称和同名（忽略大小写），名称最长 20 字。
- Room 从 2 升到 3，只新增两张表并提供 `MIGRATION_2_3`，保留旧下载记录和解析历史。

**后果**：一个作品只能属于一个合集（“移动”语义）；同一作品重新下载后仍保留原分类；合集为空时显示引导和“查看全部作品”；排序与筛选只影响显示，不改变记录。

## ADR-014：最高清晰度选项与下载进度累计

**状态**：已采纳

**背景**：默认清晰度固定为 1080P，无法一键获取作品最高画质；下载进度的 `maxBytes` 在每次回调中把“已完成字节 + 当前项字节”再相加一次，导致 UI 在下载中显示约两倍实际字节，出现“10MB 以上 / 10MB”。

**决策**：
- 设置新增 `HIGHEST_QUALITY = 0` 哨兵值；选择“最高清晰度”时先找最大短边，再在该分辨率内优先 H.264、最后按码率取最高档，不再走 `normal_1080_0` 快捷路径。
- 进度聚合拆成 `DownloadProgressTracker`：`baseBytes + currentBytes` 只计算一次，`maxBytes` 单调更新，`total` 至少等于已下载字节；UI 再用 `displayBytes` 把显示值限制在 `[0, total]`。
- 为聚合器注入时钟，便于 JVM 单元测试覆盖单文件、多文件和异常总大小三种场景。

**后果**：最高清晰度可能在无 4K H.264 时选择 4K H.265，设置页有 H.265 兼容提示；下载进度不再出现分子大于分母，最终完成值仍是实际文件字节。

## ADR-015：安全验证页自动展开与验证域名放行

**状态**：已采纳

**背景**：抖音有时在作品页弹出登录/验证 iframe 或跳转到验证域名。旧实现只依赖页面正文关键词；验证组件在跨域 iframe、Shadow DOM 或非抖音域名时检测不到，WebView 也不会自动展开，用户只能在等待页盲等。验证页还可能被主框架导航白名单拦截。

**决策**：
- `hook.js` 只把**可见**的验证码 DOM 选择器、验证 iframe src、明确的安全验证文案和验证 URL 标记为 `challenge`/`challengeReason`；
- 登录 URL、登录弹窗和“验证码登录”等文案单独标记为 `login`/`loginReason`，与安全验证分流；
- 对非主框架的 HTTPS 导航放行，验证 iframe 可以加载；主框架放行抖音域名及 bytedance/zijieapi/bytescm/bytecdn 等验证相关域名；
- `onPageStarted`/`onPageFinished` 遇到验证 URL 发出挑战状态，遇到登录 URL 只发出登录状态；
- 只有 `challenge` 自动展开 WebView；`login` 只提示“可手动显示页面登录”，绝不自动展开；页面加载超时也不再自动展开；
- 验证状态在后续图文阶段保持，直到解析结束或用户收起。

**后果**：滑块/拼图/验证码会自动展示并提示用户完成；登录页和普通慢页面不再打断用户。无法绕过验证码，验证失败仍按原错误提示处理。放行验证域名扩大了主框架导航范围，但仅限已知字节/抖音域名。

1.4.1 进一步移除了“页面完成 8 秒/加载中 15 秒”的自动展开兜底，因为它会把普通慢页面或登录页误展开；现在自动展开严格依赖安全验证信号。登录页解析最终以 `NEEDS_LOGIN` 失败并提供手动打开入口。

## ADR-016：搜索/日期/分组与列表性能策略

**状态**：已采纳

**背景**：287+ 个下载作品和 286 条解析记录时，旧资料库/下载页首屏在主线程反序列化全部快照，滚动还会不断解码本地视频封面；debug 包滚动 90 分位约 69–93ms。

**决策**：
- 搜索、日期筛选、排序和分组使用纯函数 `DownloadFeed`/`LibraryFeed`，可单元测试；下载默认最近，资料库默认最近（下载时间优先，未下载回退解析时间）；
- 搜索与日期筛选共用控制条，日期使用自绘日历；分组标题按日期、首字符、大小区间或文件数区间显示；
- 滚动进度由独立 `ScrollProgressOverlay` 读取列表状态，避免整页重组；进度用渐变胶囊+百分比而非黑色滚动条；
- Room 快照/下载任务解码、组构建移出主线程；列表项稳定 key + contentType；封面固定尺寸，滚动期间延迟新封面，视频封面远程优先、本地帧回退；
- 发布包使用 R8/资源压缩，并沿用 debug 签名以便从旧安装包覆盖升级。

**后果**：真机 release 包快速滑动 90 分位约 11–12ms；滚动期间新卡片会先显示轻量占位，停止后补封面；正式公开分发仍需换成私有 release keystore。

## ADR-017：首页视觉、协议同意门与 R8 构建提醒

**状态**：已采纳

**决策**：
- 首页使用真实 launcher 图标（AppMark）、渐变 Hero、四个功能卡片和轻量入场/光晕动画；链接输入框在非空时显示清空按钮。
- 首次启动显示全屏用户协议卡片，必须勾选同意后“同意并继续”才可用；返回键和点击外部不能绕过；不同意只能退出。
- 新增根目录 `AGENTS.md` 与 `docs/R8_BUILD_REMINDER.md`，要求后续 Agent 发布/真机性能测试使用 R8 release 包，不用 debug 包评估。

**后果**：首页首屏更紧凑，主操作按钮在常见屏幕上完整可见；首次使用有明确同意门；后续构建不容易再次误发 debug 包。

## ADR-018：Kit 浮球、后台解析与无障碍自动化

**状态**：已采纳

**背景**：用户希望在抖音内直接完成“复制分享链接 → 解析 → 按默认值下载”，并在多个作品之间排队；
Android 10+ 限制后台剪贴板读取，Android 12+ 限制后台启动前台服务，抖音页面本身也需要 WebView 环境。

**决策**：
- 使用 `FloatingAssistantService`（`specialUse` 前台服务 + 常驻低优先级通知 + `SYSTEM_ALERT_WINDOW`）
  承载悬浮球、输入框和隐藏 WebView；不使用普通后台 Service。
- 仅连播模式使用无障碍服务自动点击抖音“分享 → 分享链接”；用户必须手动在系统设置开启，
  应用内明确说明用途和关闭入口。登录页只提示，不自动展开；验证码不绕过。
- Android 10+ 剪贴板读取失败时，`ClipboardFocusReader` 短暂创建 1×1 可聚焦悬浮窗读取后立即移除；
  不使用后台轮询。检测到抖音“链接已复制成功”无障碍提示也会触发一次补救读取。
- 后台解析复用 `DouyinWebViewEngine` + `ParseController`，WebView 挂在 1×1 隐藏窗口；
  验证时扩展为全屏。队列串行，自动下载成功后等待 `DownloadRegistry` 终止再解析下一项；
  队列不落盘，进程被杀即丢失。
- 自动下载沿用 `buildFloatingDownloadRequest` 的现有默认值，并通过 `DownloadDuplicates` 自动跳过重复。
- `JobScheduler` 15 分钟 persisted 看护 + `BootCompletedReceiver` + App 启动恢复；OEM 电池/自启动限制
  仍可能阻止恢复，设置中提供忽略电池优化入口。

**后果**：
- 浮球需要悬浮窗、通知和无障碍（连播）三类敏感权限；用户可随时关闭，绝不上传页面内容。
- 抖音分享面板/按钮改版会影响连播模式，需要更新无障碍选择器；无障碍服务在部分设备应用更新后会被关闭。
- 隐藏 WebView 首次解析仍需要 10–20 秒；验证/登录时会在浮球上覆盖页面，和主解析页行为保持一致。

## ADR-019：浮球径向操作、独立浮窗、视觉设置与数据备份

**状态**：已采纳

**修订（2026-11-02）**：真机发现 ColorOS 会把浮窗的 `FLAG_BLUR_BEHIND` 扩展成整屏模糊，
不符合“只处理浮窗自身背景”的要求。因此移除所有系统跨窗口模糊调用，改由 `FrostedPanelDrawable`
在面板内部绘制磨砂/柔光/噪点；新增“完全透明”样式。状态点前台判定改以无障碍活动窗口包名为准，
内容变化事件做 400ms 节流，解决桌面残留绿色；无障碍未开启时显示空心灰环。主分析入口在不可用时隐藏，
不再显示一个变暗的重复按钮。

**背景**：v1.5.0 的浮球点击后面板承担了所有信息和按钮，状态点颜色随提示/处理状态变化，
用户难以理解；设置项持续增加后单页过长；用户还需要迁移配置和本地记录。

**决策**：
- 状态点只表示前台应用：`!appForeground && foreground.isDouyin` 为绿色，其他为灰色；
  模式用浮球图标上的“轻/连”徽标表示，进度用浮球外圈进度环表示。
- 操作按钮拆成围绕浮球的小 overlay 窗口，从浮球弹出并跟随拖动；输入/打开 App 用图标，
  分析按钮用图标 + 悬空小字；下一个/停止/结果按状态动态显示并简化文案。
- 信息浮窗与浮球分离，可拖动/缩放；先于浮球加入 WindowManager，保持浮球/操作按钮在面板之上。
  背景支持毛玻璃/半透明/完全透明/纯色、颜色、不透明度和磨砂强度，全部在面板自身 bounds 内绘制。
- 浮球大小、透明度、浮窗样式、剪贴板显示写入 DataStore；默认 48dp / 88%，比以前更小、更透明。
- 设置页按分类页签拆分；新增配置 JSON 备份（schema/versionCode/versionName/全部设置）
  和 ZIP 记录备份（manifest + JSONL 流式处理，含本地文件引用、进度和错误统计）。
- 配置缺少字段使用默认值，schema 高于当前版本拒绝导入；记录导入按主键覆盖，未完成任务转失败。

**后果**：
- 面板磨砂不依赖系统版本或 OEM 的跨窗口模糊开关，效果一致，也不会影响屏幕其他区域；
  代价是无法真实采样背后内容做模糊，磨砂为面板内部材质。
- 浮球/操作按钮/浮窗是多个 WindowManager 窗口，拖动时需同步更新按钮位置；信息浮窗与浮球独立移动。
- 状态点依赖无障碍服务；未开启时只能显示空心灰环，设置页提供授权入口。
- 记录备份只包含记录和文件位置，不打包媒体；跨设备导入后本地 URI/路径可能失效。

## ADR-020：v1.5.2 图标操作环、边缘回移与空闲休眠

**状态**：已采纳（2026-11-02）

**背景**：v1.5.1 的“分析当前视频”旁边有文字，导致按钮中心偏离浮球正上方；连播中同时存在“下一个”和
“分析当前视频”两个含义相近的入口；浮球被限制在安全边界内，无法真正贴边放置；浮窗最小尺寸偏大，
浮动设置滑块使用固定档位，调节不够细。

**决策**：
- 操作环全部改为 42dp 纯图标，文字只保留在无障碍 `contentDescription` 中；“分析当前视频”在 0° 时
  位于浮球正上方。删除“下一个”按钮。
- 连播任务繁忙时仍显示“分析当前视频”；点击继续自动点击分享并把当前作品加入队列，
  用同一个入口替代“下一个”。分享自动化进行中时按钮暂时禁用，避免并发自动化。
- 拖动不再使用固定安全边界，只保留至少 24dp 可见；点击边缘浮球时用 220ms 动画移动到按
  按钮环实际半径计算的安全位置，再展开操作环。拖动时收起操作环，避免按钮遮挡。
- 新增空闲休眠：默认 45 秒无操作后移动到最近边缘并降低透明度；点击唤醒、移回安全位置并展开操作环。
  休眠由 `postDelayed` 调度，任务/操作环/输入框/浮窗打开时取消，不做周期性 tick。
- 浮窗默认 280×112dp，边距缩小；最小宽度 150–260dp、最小高度 64–160dp 可在设置中调整。
- 新增按钮距离 0–24dp、整体旋转 -60°–60°、休眠时长 0–180 秒设置；浮动设置滑块全部改为连续调节。
- 配置备份新增 5 个字段（共 27 个）；仍为 schema 1，旧配置缺字段使用默认值。

**后果**：
- 操作环更简洁，分析入口唯一；分享自动化期间按钮禁用，用户需要等待本次复制完成。
- 边缘点击多一次 220ms 位移动画；拖动到边缘后操作环自动收起，需要再次点击展开。
- 休眠移动/唤醒使用 `ValueAnimator` 更新 WindowManager 参数，未引入每帧对象分配；窗口小，开销可控。
- 去掉文字后按钮更依赖图标和无障碍描述，首次使用仍需学习；设置页提供距离/角度预览式调节。
- 浮窗最小高度 64dp 时内容区很小，复杂状态需要滚动；这是用户可调边界带来的取舍。

## ADR-021：全角度操作环、环上关闭按钮与纵向作品预览

**状态**：已采纳（2026-11-03）

**背景**：v1.5.2 的按钮整体旋转只支持 -60°–60°，用户希望完整旋转操作环；浮窗右上角的“×”
与浮球操作环分离，显示浮窗时还要去面板角落关闭；解析/下载时“停止”按钮与相邻“打开”按钮
角度间隔不足，出现相交；“点击浮球”固定同时打开浮窗，无法按使用习惯关闭；下载页作品预览
一次只能看一个作品，不能像抖音一样上下滑动切换。

**决策**：
- 按钮整体旋转扩展到 -180°–180°，仍使用连续滑块；存储、配置备份和恢复都使用同一范围。
- 删除面板内的“×”，新增 `CLOSE_PANEL` 操作环按钮。`panelVisible` 时从浮球上方弹出，
  点击调用 `hidePanel(notify = true)`，通过 `FloatingAssistantBus.expanded` 同步服务状态。
- 抽出纯 Kotlin 的 `FloatingActionLayout`：每个动作有偏好角度；出现停止时打开按钮从 0° 移到 -14°，
  结果从 90° 移到 94°，停止放在 40°；出现关闭按钮时关闭在 -144°、输入从 180° 移到 162°；
  所有活动按钮保证至少 54° 间隔。`FloatingOverlayController` 加用户旋转并计算坐标，
  位置变化用 180ms 减速动画；拖动/浮球回移动画期间即时更新，不做动画延迟。
- 新增 `floatingTapShowsPanel` 设置（默认 true）。`toggleActions()` 只在开启时自动 `showPanel`；
  关闭后点击浮球只弹操作环，但任务状态仍通过 `expanded` 自动显示浮窗。
- 下载页作品预览改为 `VerticalPager`，页源为当前 `visibleGroups`（即下载页筛选/排序后的顺序），
  每页独立 `WorkPreviewPage` 状态与顶部按钮；`detailsOpen` 时禁用 pager，返回键先关闭详情；
  `beyondViewportPageCount = 1` 预组合前后各一页，减少切换时的播放器创建卡顿。
- 预览当前页默认自动播放；`DouyinVideoPlayer` 在 `pause` 变为 false 时无条件 `play()`，
  预组合的相邻页从创建起即暂停，切换后新作品自动开始播放。不添加播放完毕自动切换：
  视频/动图/BGM 均保持单作品循环，只有用户上下滑动才切换。

**后果**：
- 操作环按钮数量最多 6 个时仍可能接近屏幕边缘；`safeOrbTarget` 已按按钮环半径预留安全区，
  点击边缘浮球会先移回安全位置。
- 全角度旋转可把分析按钮转到下方，这是用户显式设置的结果；0° 仍保持分析按钮在正上方。
- 关闭按钮成为操作环成员后，浮窗必须通过浮球关闭；若操作环未展开，需要先点浮球。
- 纵向预览预组合前后各一页，内存和 ExoPlayer 数量最多 3 个；非当前页暂停，避免声音叠加。
  当前页自动播放，切换后新作品自动开始；低端设备首次切换到未缓存视频仍可能短暂缓冲。
- 预览页顺序与打开时的下载页 feed 一致；若预览期间下载任务导致排序变化，Compose pager 以
  `awemeId` 作为 key 保持当前作品，列表增删不会崩溃。

## ADR-022：预览首次自动播放与退出卡顿优化

**状态**：已采纳（2026-11-04）

**背景**：v1.5.5 的预览在打开后经常处于暂停状态，需要点击播放或切换作品才开始；退出预览回到下载页时也有明显掉帧。
原因是 `beyondViewportPageCount = 1` 预组合的多个 `ExoPlayer` 在创建时都设置了 `playWhenReady = true`，
会同时请求音频焦点，后来创建的播放器使当前作品丢失焦点并暂停；同时 `WorkPreviewDialog` 的预览状态在
`DownloadsScreen` 顶层读取，关闭时会让整个下载 feed 重新组合。

**决策**：
- 所有 `DouyinVideoPlayer` 创建时 `playWhenReady = false`；只有 `pause = false` 的当前作品主动 `play()`。
  预组合的相邻页保持暂停，不请求音频焦点。
- 保留 `beyondViewportPageCount = 1`，让相邻页的播放器提前准备，切换时首帧更快；当前页切换时旧播放器暂停、
  新播放器自动播放。
- 图文 BGM 仍由 `AutoLoopingAudio` 只在当前页启用；LivePhoto 仍由用户点击播放。
- 把预览打开请求移入独立 `PreviewOverlay`，只有该层读取 `previewRequest`；关闭预览只重组预览层，
  下载列表、合集芯片和卡片 feed 不参与重组。
- 预览播放器仍然只会在当前页播放，退出时释放已暂停的预组合播放器，避免多路音频和释放正在播放播放器的争抢。

**后果**：
- 打开预览和切换作品后视频自动播放，图文 BGM 自动循环；音频焦点始终只有当前作品。
- 真机 R8 release 视频预览退出 90/95/99 分位约 17/19/26ms，legacy 卡顿帧 0.76%；
  上下切换约 21/25/40ms，legacy 8.42%（含视频首帧准备）。
- 预组合页仍会创建最多 3 个 ExoPlayer 并占用解码器，但都处于暂停；低端设备首次切换未缓存视频仍可能短暂缓冲。
- 预览打开状态由 `PreviewOverlay` 管理；关闭后底层下载页保持原有滚动位置和筛选状态。

## ADR-023：大数据量下的轻量查询与隐藏 WebView 看门狗

**状态**：已采纳（2026-11-07）

**背景**：浮球队列连续解析 45 条后，隐藏 WebView 从某一刻开始所有页面都超时，直到应用进程被系统杀掉并重启
才恢复。现场排查发现：历史记录达到 800+ 条时，首页和下载页仍通过 `SELECT * FROM awemes` 读取全部完整
`snapshotJson`；队列每保存一条作品都会触发 Room 失效重查。真机上复现了 Java 堆 OOM（`CursorWindow.getString`，
384MB 上限），同时 WebView 渲染进程没有崩溃、一直存活到应用被系统杀掉，说明它是被内存/资源压力拖死而不是崩溃。
另外，`readPageState` 没有超时，渲染进程无响应时会一直挂起；队列也没有重建 WebView 的逻辑。

**决策**：
- `HomeScreen` 改为 `observeRecent(6)`，SQL 使用 `LIMIT 6`，只读取首页真正需要的记录。
- `DownloadsScreen` 的标签/收藏改用 `AwemeMeta` 投影，不读取 `snapshotJson`。
- `LibraryScreen` 列表只加载 `AwemeMeta`；点击作品时再按 `awemeId` 读取并解码完整快照。
- `FloatingParseQueue` 的重复下载检查改为 `tasksForAweme(awemeId)`，不再 `allTasks()` 加载全部下载历史。
- `DouyinWebViewEngine.readPageState()` 增加 3 秒超时；`ParseController` 连续 2 次读取不到页面状态即抛出
  `WEBVIEW_UNAVAILABLE`。`FloatingParseQueue` 连续 2 次超时/无响应后销毁并重建隐藏 WebView。
- 新增“解析队列间隔”设置（0–60 秒，默认 5 秒），每条完成后再等待指定时间处理下一条。

**后果**：
- 840 条解析记录下，首页 PSS 约 89MB、资料库约 119MB，不再出现全量快照加载导致的 OOM；下载页仍需解码
  下载任务本身，PSS 约 287MB，但不再读取全部作品快照。
- 单条作品打开时会多一次 Room 查询/解码，换来列表内存显著下降。
- 队列遇到卡死的 WebView 会先快速失败（约 3–6 秒）并自动重建，不再让后续作品逐个等到 45/180 秒超时。
- 默认 5 秒间隔会拉长大队列的总体耗时；用户可在设置中调到 0 秒恢复原来的连续处理速度。
